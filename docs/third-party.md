# Third-party components and build tooling

The self-contained Windows build bundles Microsoft .NET 10.0.13, ASP.NET Core and Windows Desktop runtime components (10.0.12 through version 0.2.1). The release's licenses directory contains DOTNET-LICENSE.txt, DOTNET-ThirdPartyNotices.txt and QRCODER-LICENSE.txt copied from the pinned toolchain/package. QRCoder 1.8.0 uses the MIT license: https://github.com/codebude/QRCoder/blob/master/LICENSE.txt. The mobile build uses pinned Vite/TypeScript tooling; those tools are not required on the installed PC. Exact dependencies are recorded in lockfiles.

Installer compiler: Inno Setup 7.1.0 x64, official immutable release https://github.com/jrsoftware/issrc/releases/tag/is-7_1_0. Download SHA-256 `0362a383ed217d4c4239b5933866dd96d3eb2102737da92f80f6057a4b40df2f`, checked against its official `.issig` and valid Pyrsys B.V. Authenticode signature. Compiler is kept in ignored `.tools/`; no global development tool is replaced. This project's local personal build uses Inno Setup's noncommercial terms. Commercial build/distribution use requires checking/purchasing the appropriate compiler license: https://jrsoftware.org/isdl.php. The generated installer is unsigned; the compiler's signature does not sign the application.

NSIS 3.13 was considered; its download returned HTML rather than a checksum-verifiable ZIP on this host, so it was not extracted or executed. Release tooling uses the verified Inno compiler instead.

Phase 1 adds no shipped third-party dependency and keeps the existing SDK/frontend/QRCoder versions. The shared Host uses the existing ASP.NET Core framework; test runners and CI use Python's standard library (3.13+ for strict TLS). Optional locally downloaded validation tools are not distributed with the application.

## Phase 2 desktop dependencies (2026-10-13)

`PcController.Desktop` pins Avalonia.Desktop and Avalonia.Themes.Fluent **12.1.4** (MIT), with QRCoder **1.8.0** (existing MIT dependency; the shell uses its PNG renderer, not System.Drawing native APIs). `PcController.DesktopTests` separately pins Avalonia.Headless **12.1.4** (MIT); it is test-only. Version selection/support sources and OS baseline decisions are in [desktop-shell.md](desktop-shell.md). The SDK/Node/npm/public Windows version remain unchanged.

Desktop lockfiles record these principal transitive dependencies: Avalonia platform/accessibility packages 12.1.4 and BuildServices 11.3.2 (MIT), SkiaSharp/native assets **3.119.4** (MIT managed binding with native third-party notices), HarfBuzzSharp/native assets **8.3.1.3** (MIT binding with native third-party notices), MicroCom.Runtime **0.11.6** (MIT), Tmds.DBus.Protocol **0.94.1** (MIT), and Microsoft System.Drawing.Common/SystemEvents **6.0.0** (MIT, inherited from QRCoder). Windows ANGLE natives **2.1.27548.20260419** carry their packaged license including BSD notices; they are in Avalonia's cross-platform restore graph, not a new Windows UI migration. NuGet package metadata/licenses were inspected; feed audits report actual results in the roadmap log.

Sources: [Avalonia license](https://github.com/AvaloniaUI/Avalonia/blob/12.1.4/licence.md), [SkiaSharp](https://github.com/mono/SkiaSharp), [HarfBuzzSharp](https://github.com/mono/SkiaSharp/tree/main/source/HarfBuzzSharp), [MicroCom](https://github.com/AvaloniaUI/MicroCom), [Tmds.DBus](https://github.com/tmds/Tmds.DBus). Native redistributions must retain the pinned packages' `LICENSE.txt` and `THIRD-PARTY-NOTICES.txt`, plus .NET and QRCoder licenses and Avalonia/ANGLE notices where shipped. Phase 2 creates no new public distributable; Phase 5 packaging must collect and verify these actual notices, rather than assuming managed MIT licenses cover all native components.

Avalonia BuildServices collects build-time usage metadata by default and has no deployed-app telemetry. Repository Python/PowerShell entry points and CI now set its documented FOSS opt-out (`AVALONIA_TELEMETRY_OPTOUT=1`); set that environment variable for direct dotnet builds too. Initial dependency-selection builds used the vendor default. No Accelerate license or proprietary UI package is used. [Official telemetry source and opt-out](https://github.com/AvaloniaUI/Avalonia.BuildServices).

## Phase 3 macOS native bridge and development candidate (2026-10-13)

No NuGet/npm version changes are added. The authored Objective-C bridge links the OS-provided AppKit, ApplicationServices/Core Graphics, Carbon text-input/keyboard-layout services, Security Keychain Services and SystemConfiguration frameworks; Apple framework binaries are not redistributed. Xcode Command Line Tools/clang are build prerequisites, not bundled runtime dependencies. Input uses public Quartz/Accessibility APIs; legacy file-based Keychain APIs remain supported but deprecated, deliberately chosen for unsigned local development. A data-protection Keychain/signing-entitlement migration is not implied.

`scripts/package-macos.py` collects the pinned NuGet packages' actual license/native notice files, .NET license/notices, repository MIT license and dependency inventory into the candidate, and includes the exact Avalonia 12.1.4 license from [its tagged source](https://github.com/AvaloniaUI/Avalonia/blob/12.1.4/licence.md), retained at `docs/licenses/Avalonia-12.1.4.md`. Packages bundle .NET 10.0.13 (10.0.12 in earlier candidates) and the existing Avalonia/Skia/HarfBuzz/QRCoder graph. Test-only Headless, recording adapters and NativeTarget are not in the production package. Outputs are provisional unsigned/not-notarized local artifacts; Phase 5/public packaging still needs distribution/signing/license acceptance.

API design references: [Core Graphics event functions](https://developer.apple.com/documentation/coregraphics/core-graphics-functions), [Accessibility trust](https://developer.apple.com/documentation/applicationservices/1460720-axisprocesstrustedwithoptions), [Mac Keychain implementations (TN3137)](https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains), [SecItemCopyMatching](https://developer.apple.com/documentation/security/secitemcopymatching(_:_:)), [UCKeyTranslate](https://developer.apple.com/documentation/coreservices/1390584-uckeytranslate), [NSWorkspace lifecycle](https://developer.apple.com/documentation/appkit/nsworkspace), [SystemConfiguration](https://developer.apple.com/documentation/systemconfiguration). UCKeyTranslate is used for logical Command-layout resolution without changing input sources; native target/layout acceptance remains separate.

## Phase 4 Linux system components (2026-10-13)

The authored C bridge dynamically links Ubuntu-maintained GLib/GIO (LGPL-2.1-or-later), libsecret (LGPL-2.1-or-later), XCB/libxcb XTEST (MIT/X11), and libxkbcommon/xkbcommon-x11 (MIT). GNOME Keyring and xdg-desktop-portal-gnome are separately installed desktop services, not bundled code; provider encryption properties and protocol limits are reviewed in [Linux setup](linux-setup.md). GLib, libsecret and libxkbcommon upstream licenses and Ubuntu `/usr/share/doc/<package>/copyright` govern the actual installed revisions. GTK 3 and Xvfb are test-only system dependencies. No source from Mutter/GNOME Keyring is copied into this project, and no native library/service/package is redistributed in this phase. Existing Avalonia/toolchain pins and public package notices remain unchanged. Any later Linux package must inventory its actual runtime/dependencies and include required license texts before distribution.


## Phase 5 source candidates (2026-10-13)

Supported native feature adapters and provisional packages are described in [the release-readiness handoff](release-readiness.md). Since version 0.3.0, releases publish experimental macOS/Ubuntu archives alongside the Windows companion; their native/phone/LAN acceptance remains pending. Mac Core Audio/native system media/player shortcuts/LaunchServices/login registration/sleep and Linux libpulse/MPRIS/player shortcuts/restricted GIO/XDG/logind use real platform services with backend denial and final native readiness/permission checks. Mac restart/shutdown stay unavailable; Linux power requires `Can* == yes`, `interactive=false`, no inhibitor override. Launcher wire input is still configured IDs only; no remote path/arguments/shell. Native dependencies/signing/login eligibility/actual player and physical power acceptance remain separate from recording/source-table/protocol/package checks.

Readiness transitions now force replacement of the capability snapshot even on unchanged loopback bindings; old ownership/listeners stop and replacement starts paused. v1 fields, budgets/reserved cancellation, original-session authentication checks, device-bound confirmation/countdown/cancellation and failed cleanup retention remain. Optional login start never preserves LAN approval/Wayland consent or resumes control. Provisional manifests record version/base revision/dirty source/file hashes; no tag/public release is created. Windows adapters, DPAPI and packaging remain intact. Real GNOME/phone/LAN/installed/Intel/CI gates stay visible.

The authored macOS bridge additionally links system CoreAudio, IOKit and ServiceManagement frameworks (not redistributed). Linux additionally dynamically links OS-provided libpulse (LGPL-2.1-or-later); PulseAudio/PipeWire and MPRIS/logind services are OS dependencies, not bundled binaries. No new NuGet/npm dependency or toolchain version is introduced. Archive notice collection retains actual dependency paths to avoid overwriting different native notices, and includes locked inventories plus .NET/PCRemote/QRCoder/Avalonia/Skia/HarfBuzz notices. Runtime is 10.0.13 from SDK 10.0.402. SMAppService requires code-signing eligibility; no Developer ID/notarization/repository signature is claimed. See exact actual checks in the dated roadmap/release evidence.
