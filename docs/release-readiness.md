# Multi-platform release readiness

Version **0.4.2** is the current public preview: the Windows companion remains the primary platform, and macOS ARM64/Intel and Ubuntu 24.04 x64 archives are published as **experimental** builds of the shared companion. 0.4.0 added the phone remote's Air pointer (gyroscope mouse) and 0.4.1 corrects its gyroscope axis order; the evidence is synthetic-sensor browser checks on every OS plus an iPhone confirming the flat-grip directions against the macOS companion, with the rest of the phone acceptance table pending. 0.4.2 changes only the macOS companion's native bridge: the peer-to-peer Wi-Fi (`awdl`/`llw`) interface records that macOS re-publishes about every 76 s no longer revoke the session's LAN approval (verified side by side against the installed 0.4.1 bridge on the developer's Wi-Fi: 15 revocations over three bursts before, 0 after; a paired phone across those bursts on the installed build is still pending). This page separates implemented source, automated evidence actually obtained, published packaging and the native/manual acceptance that is still pending. Candidate outputs (explicit `candidate` filename, dirty-source manifest) are never published; release assets come from `--final` builds of the exact tagged commit.

## Implemented feature contract

| Feature | macOS source candidate | Ubuntu 24.04 x64/GNOME source candidate |
| --- | --- | --- |
| System volume/read-back | Core Audio default writable output, 0–100, unmutes on level change; read-only HDMI/output controls unavailable | Native libpulse against PulseAudio or PipeWire-Pulse default sink; preserves channel balance, 0–100, unmutes; missing server/sink unavailable |
| General playback | Native system media keys; OS chooses the active media recipient | MPRIS: one playing controllable player, otherwise exactly one eligible player; ambiguous selection fails |
| Player profiles | Verified OS-specific shortcut tables; matching frontmost VLC/Stremio/browser bundle required; browser tab/player focus still local | VLC/YouTube/Stremio shortcut tables through consented input; focus the matching native player, especially on Wayland where there is no global focus inspection |
| Configured launcher | Locally selected `.app`, LaunchServices activation request, no arguments/remote paths | Locally selected `.desktop`, GIO launch of ELF application, no terminal, interpreter, wrapper, D-Bus activation or arbitrary arguments; only file/URI field codes and VLC's `--started-from-file` flag accepted |
| Optional login start | `SMAppService.mainAppService`, local Login Items approval/code-signing eligibility required | Exact-executable GNOME XDG autostart entry, opt-in, own matching entry only, private file, refuses symlinks/conflicts |
| Power | Sleep only: console-user IOKit API, readiness and sleep support rechecked. Restart/shutdown backend-denied | logind Suspend/Reboot/PowerOff only for `Can* == yes`, rechecked at dispatch, `interactive=false`; challenge/no/na fail |

Every startup remains paused. Login start does not retain LAN approval, portal consent or a controller. No root operation, shell execution, permission fallback, automatic certificate trust, forced app termination, input bypass or test service enters production. The existing Windows WPF companion and packaging stay in place.

Player tables were checked against [VideoLAN's OS-specific defaults](https://github.com/videolan/vlc/blob/3.0.x/src/libvlc-module.c), [YouTube shortcuts](https://support.google.com/youtube/answer/7631406?hl=en), and [the previously inspected Stremio shortcut source](https://github.com/Stremio/stremio-web/blob/21c8a53b026a85745e60203d94786835782277f4/src/common/Shortcuts/shortcuts.json). This is source verification; actual installed-player playback, custom shortcuts, layouts and focus behavior require the manual checks below. General uses [MPRIS permission properties](https://specifications.freedesktop.org/mpris/latest/Player_Interface.html) on Linux. Mac sleep follows [IOPMSleepSystem's console-user boundary](https://developer.apple.com/documentation/iokit/1557121-iopmsleepsystem). Mac restart/shutdown have no reviewed adapter and stay unavailable.

## Build and packages

Pinned inputs: SDK 10.0.402 (runtime 10.0.13), Node 24.21.0/npm 11.19.0, Avalonia 12.1.4 and existing lockfiles. `Directory.Build.props` declares `PcRemoteVersion`; Desktop inherits it and Windows' explicit version must match. Packaging verifies exact tools, rebuilds the bundled remote, publishes self-contained .NET/ASP.NET Core, retains lockfiles, collects actual managed/native licenses, checks native architectures, rejects private/debug files and scans artifact bytes for credential/private-key patterns. ZIP/TAR integrity, actual archive member bytes and SHA-256 checksums are checked. Linux ownership headers omit build-user metadata. Mac ZIPs retain only inventoried public code-signature attributes required by the flat .NET bundle, using the [public copyfile PACK callback](https://github.com/apple-oss-distributions/copyfile/blob/main/copyfile.3); unrelated provenance/Finder/ACL data is omitted, and the extracted bundle seal is verified. `candidate-manifest.json` records base revision, dirty state, source-tree digest and per-file hashes; `--package-info` reads the bundled executable's product/revision/runtime without listeners or input.

```sh
# On a Mac with Xcode Command Line Tools:
python3 scripts/package-macos.py --rid osx-arm64
python3 scripts/package-macos.py --rid osx-x64
# On Ubuntu x64 with native build prerequisites:
python3 scripts/package-linux.py
```

Outputs go to new ignored `artifacts/candidate-<version>-<rid>-<UTC timestamp>/` directories. `--final` refuses a dirty or untracked source tree and instead writes `artifacts/release-<version>-<rid>-<timestamp>/PCRemote-<version>-<rid>.zip` or `.tar.gz` plus `PCRemote-<version>-<rid>-manifest.json` (`candidate: false`, exact revision, `sourceDirty: false`); `check-package.py --final` requires the checked-out commit to match. The CI `workflow_dispatch` input `final` runs the same packaging on clean hosted runners as workflow artifacts only, without tagging or publishing. Mac ZIP contains `PC Remote.app`; Ubuntu TAR.GZ contains `PCRemote-linux-x64/`. Keep all adjacent runtime/native/web files. Linux archives require the system GNOME services and native libraries listed in [Linux setup](linux-setup.md); they do not bundle a desktop, portal, keyring or PulseAudio server. No DMG/DEB is added: an archive permits reversible per-user validation without an installer/uninstall lifecycle that has not been accepted. No Developer ID credentials, notarization, Linux repository signature or distribution signing is available. Mac candidates receive a local ad-hoc bundle seal, verified with codesign, requiring no signing credential; it is not Developer ID/notarization or distribution trust. SDK ad-hoc executable signatures do not change that status.

The source/package pattern scan is useful evidence, not a replacement for a full secret scanner before publication. CI builds/tests and creates candidate (or, with the `final` dispatch input, release-named) workflow artifacts on supported hosted OSes, retaining Windows regression/packaging. Observed hosted runs cannot prove interactive GNOME, physical phone, input cleanup, power or installed acceptance.

## Separately authorized publication

Versions 0.3.0 through 0.4.2 followed this procedure; repeat it for every later version. Choose a new three-component version only after publication is authorized. Synchronize shared/Windows versions, Windows package default and installer fallback; README status/downloads/commands, both agent files, releases, dated evidence, affected setup/protocol/notices and `.github/`. Keep all gaps visible and preview status appropriate. Complete `AGENTS.md` and the release checklist; run documentation, Release/regression/strict-TLS/dependency/runtime advisory/secret/package checks.

Commit **all** corresponding source/docs to `main` before final packaging. Build final assets from that exact clean commit; verify each DLL informational revision, package inventories, runtime versions, licenses and aggregated checksums. Use `--final` packaging (or the CI `final` dispatch) instead of renaming candidates. Create a new annotated `vX.Y.Z` tag at that commit, push source/tag, attach accurate Windows/Mac/Ubuntu assets and a combined `SHA256SUMS.txt`, publish within the authorization, then independently verify public tag/commit, preview status, every URL/size/digest and rendered notes. Never move a published tag or replace its binaries.
