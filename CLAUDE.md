# Claude instructions for PC Remote

Read and follow [AGENTS.md](AGENTS.md) before editing this repository. It is the shared source of project, validation, security, and publishing instructions. Also read [README.md](README.md), [release publishing](docs/releases.md), and the [release checklist](docs/release-checklist.md) when preparing a release.

Current app version: `0.4.2`.
Current public release: [v0.4.2 preview](https://github.com/maamouribilel/pc-remote/releases/tag/v0.4.2) — Windows companion plus experimental macOS ARM64/Intel and Ubuntu 24.04 x64 archives; the macOS companion keeps its approved network across the peer-to-peer Wi-Fi (`awdl`/`llw`) record updates that dropped it within about a minute on 0.3.6–0.4.1. Windows, Ubuntu, the phone remote (Air pointer corrected in 0.4.1) and the protocol are unchanged.


- Public documentation and GitHub metadata describe every supported platform and browser with its actual status: Windows primary; macOS and Ubuntu experimental; iPhone Safari and its Home Screen app verified on hardware; Chromium-based browsers covered by automated checks at phone and desktop sizes; Android, iPad and Firefox untested. Never present the product as Windows-only or iPhone/Safari-only, and never claim a device, browser or platform that has not been verified. Keep companion UI text device-neutral except where a step is genuinely platform-specific.
- `docs/promo/` holds the illustrated 28-second promo (16:9 and 9:16 MP4s) and its generator in `docs/promo/source/`. It redraws the UI and synthesizes its sound, so it is neither README demo media nor evidence. Keep its on-screen claims in line with the support matrix, and rebuild it with `docs/promo/source/build.sh` when they change.

- Keep user documentation focused on the current controls: `docs/setup.md` covers Touch/Air and pairing, `docs/demo.md` is the hands-on tour, and `docs/development.md` holds build/test detail. README demo media must be captured from the real bundled UI, versioned under `docs/assets/`, with dated provenance in `docs/assets/README.md`; label recording adapters and synthetic motion explicitly and retain historical captures.

## Portable backend, shared shell and platform development (Phases 1–5)

- Version 0.4.2 distributes the Windows WPF companion as the primary platform plus experimental macOS/Ubuntu archives of the shared shell. `PcController.Host` and `PcController.Core` target `net10.0`; WPF/UI and native Windows integration stay in App/Windows. Read `docs/portable-host.md` and the dated `MULTIPLATFORM_PLAN.md` execution log before continuing the migration.
- Shared host startup requires explicit `HostServices`; use `WindowsHostFactory` for the WPF companion. Keep DPAPI formats, ACLs, Schannel key loading, trusted roots and remembered devices intact. Certificate issuance/renewal is separate from OS key storage. Never substitute temporary test storage or recording adapters in production.
- Pointer/media/launcher preferences live in Host; Windows paths, discovery, shortcut/media key mappings and native APIs remain adapters. Preserve v1 wire semantics and the additive authenticated capability contract. The browser now consumes additive authenticated v1 capabilities/readiness; preserve independent action gating and Windows legacy compatibility.
- Use the pinned SDK 10.0.402 (runtime 10.0.13, updated 2026-10-13 for the .NET security release including CVE-2026-58280), Node 24.21.0 and npm 11.19.0. `python3 scripts/portable.py build`, `test`, `audit`, and `tls` support native macOS/Linux tools; strict TLS needs Python 3.13+. PowerShell 7 build/test automatically select portable projects off Windows; use `-Portable` on Windows. Keep the full Windows solution/regression job.
- Portable fixtures are test-project-only, loopback-only and temporary. Recording tests, container checks, cross-compilation and configured CI jobs cannot establish native input, DPAPI execution on Windows, physical-phone/LAN or installed-app acceptance. Record actual platform results and pending checks separately; do not start the next roadmap phase automatically.
- `PcController.Desktop` pins Avalonia 12.1.4 and retains the Windows WPF companion. Read `docs/desktop-shell.md`. macOS now composes real Quartz/Accessibility input and Keychain-backed storage, starts paused and requires explicit network approval. Linux has real XCB/XTEST, Remote Desktop portal and GNOME keyring source composition; real Ubuntu x64/GNOME X11 and Wayland acceptance remains pending. Read `docs/linux-setup.md`. Read `docs/macos-setup.md`. No test adapter/store may enter production composition.
- Network approval is explicit and session-only; invalidate it on connectivity/identity changes (macOS: network keys except Wi-Fi `LinkQuality` signal updates, `AirPort` record/field updates that keep the same joined network name and, since 0.4.2, the `State:` records of the peer-to-peer `awdl<n>`/`llw<n>` interfaces, which carry only a link-local address and were re-published about every 76 s on the user's Mac on 2026-10-15; system sleep/wake, session switch, power-off), pause/release ownership and stop old LAN listeners before replacement. Space/full-screen, display and readiness (Secure Input/permission) transitions pause and release input but must not revoke LAN approval; pause-only transitions (Space, display, Secure Input, login screen, inactive session) must also keep the running host, its pairing link and pending pairing approvals, and the shell distinguishes a missing Accessibility permission (onboarding) from a transient session block, which the bridge reports as one named reason (`pc_session_state`); a failed system-wide focus query falls back to the frontmost application because permission is rechecked live before every post. Only an Accessibility permission or storage change rebuilds the capability snapshot. Validate platform identity/notification coverage before production LAN startup; certificate SANs must cover every exact binding. Do not infer trust from private addresses.
- Use `python3 scripts/portable.py desktop`, `desktop-test`, `desktop-fixture` (test-only), and `browser-capabilities`; PowerShell supports `test.ps1 -Desktop`. Run loopback HTTP suites sequentially on port 8443. Record native shell startup separately from headless/recording checks and native control. macOS uses its native bridge, per-user single-instance lock and lifecycle/storage readiness monitor. Linux source adapters retain Phase 4 native gates; do not call the Wayland gate complete from D-Bus/Xvfb evidence. Releases since 0.3.0 publish Phase 5 features as experimental previews; never describe them as stable platform parity or native acceptance. The macOS/Linux window follows the Windows dashboard (`docs/desktop-shell.md` window layout); keep its automation IDs stable and run `desktop-test` after UI changes. SIGTERM/SIGINT/SIGHUP, native Quit and OS logout use the same graceful Exit; only failed input cleanup cancels it.
- The phone remote's **Air pointer** (gyroscope mouse, since 0.4.0, designed in `AIR_POINTER_PLAN.md`) is phone-client only: it feeds the existing v1 `pointer.move` aggregate and adds no message, field, capability or Host setting. Keep the hold-to-point clutch, never re-engage pointing automatically, read sensors only while Air is selected on a visible Touchpad tab with control enabled, send only rounded pixel deltas, and keep `accelerometer`/`gyroscope` allowed for `self` if a `Permissions-Policy` header is ever added. `python3 scripts/portable.py remote-unit` runs the page-less math checks; `browser` also runs `air.spec.ts` on its own fixture instance. Sensor conventions measured on an iPhone on 2026-10-15 (`AIR_POINTER_PLAN.md`): `rotationRate` alpha/beta/gamma are rotation about x/y/z on every platform (current W3C draft; WebKit, Chromium and Gecko sources; 0.4.0 used the stale alpha-about-z wording), WebKit on iOS reports gravity toward the ground so `detectGravitySign` seeds −1 there while the per-hold resolver remains, `event.interval` is seconds on iOS, and the One-Euro filter runs before the 2 °/s soft deadzone; keep that order and sign handling. Synthetic sensors are not device evidence: the flat-grip directions are confirmed on an iPhone, while the remaining Phase 4 acceptance rows (measured table, other grips, lifecycle, Safari/Home Screen permission, Android) stay pending until recorded in the plan's log.

- macOS native builds require Xcode Command Line Tools; `PcController.MacOS/native/bridge.m` uses public Quartz/Accessibility, Keychain and SystemConfiguration/AppKit APIs. Never use Windows key codes/wheel events or request Input Monitoring/Screen Recording/Location as a compatibility fallback. Keep Command-layout resolution and Unicode scalar handling. Text Input Source/keyboard-layout APIs may only run on the main thread (they trap off the main queue on current macOS); worker threads read the bridge's main-thread layout cache.
- Mac storage uses a non-syncing key in the default per-user file-based Keychain and path-authenticated AES-GCM envelopes under `~/Library/Application Support/PC Remote` (0700/0600, umask 077, no symlinks). Locked/missing/denied storage must stop listeners; missing keys/roots never silently reset installation trust. A changed ad-hoc code identity after an update is refused silently; only the explicit local **Allow Keychain access after update…** action may permit macOS's own Keychain dialog for the existing key. Never edit ACLs, unlock, create or replace keys in that path. Preserve Windows DPAPI formats. Event tracking survives listener replacement, and failed cleanup blocks Resume/graceful Exit.
- Run `scripts/portable.py mac-test`, `mac-storage`, and Python 3.13+ `mac-tls`; `mac-smoke` requires Accessibility and creates a guarded disposable Cocoa target. Abort test actions on target focus loss; permit only tracked up events for safety cleanup. Run all HTTP suites sequentially on 8443. Never relabel unavailable native/phone/lock/roaming/Intel acceptance as passed.
- `python3 scripts/package-macos.py` creates a new ignored version-aware provisional Apple Silicon `.app`/ZIP/checksum/manifest; `--rid osx-x64` builds the Intel bridge/runtime separately. `scripts/package-linux.py` requires Linux x64 and creates an Ubuntu self-contained archive. No Developer ID signature/notarization or distribution signature is claimed; only `--final` outputs from a clean tagged commit may become release assets. `scripts/sign-macos-local.py` re-signs an installed bundle with a per-Mac self-signed identity so the Accessibility entry survives updates (the Keychain partition list still names each build's cdhash, so that approval stays once per build); it is local-only, refuses `CI=true` and never produces release assets. Run `scripts/check-package.py --rid <rid>`; cross-build checks are separate from native startup. `--final` (packaging and `check-package.py`) produces release names/manifests only from a clean committed tree; the CI `workflow_dispatch` input `final` builds them on clean runners without tagging or publishing.



- Linux native builds require `cc`, `pkg-config`, GLib/GIO, libsecret, XCB/XTEST and libxkbcommon-x11 development packages. Runtime is unprivileged: actual logind session/backend, GNOME ScreenSaver, NetworkManager and session-bus observation are required. Wayland uses consented RemoteDesktop `Notify*` input, never XWayland/uinput/root fallback; no EIS/Notify mixing. Phase 5 media/volume/launcher/logind power/autostart use real native services; missing permission/services fail closed. Native runtime additionally needs libpulse/PulseAudio or PipeWire-Pulse.
- Linux storage requires the reviewed same-user GNOME provider, unlocked persistent login collection and encrypted restricted login-keyring format. Blank-password/plaintext, missing/locked/unsupported providers fail; Secret Service is not DPAPI-equivalent. Linux AES-GCM files use 0700/0600 and path AAD; preserve roots/devices and reject missing keys/roots. No fixture seam appears in the production bridge.
- Linux text is disabled until explicit local GTK Unicode opt-in. Preserve independent capabilities and target limits; do not claim universal Unicode or Wayland receipt from portal calls. Failed cleanup retains tracking and blocks Resume/Exit; interrupted compose or ended-backend tracking needs explicitly verified local recovery, never silent clearing or old ups in a replacement session.
- `scripts/portable.py linux-test`, `linux-x11`, `linux-portal`, `linux-storage` separate faults, private Xvfb/GTK (US/French), private fake-portal protocol and real disposable encrypted GNOME keyring/TLS. Python 3.13+ adds strict Linux storage TLS. Real Ubuntu x64/GNOME X11, Wayland text/cleanup, lock/suspend/roaming/tray and physical-phone/LAN gates remain pending. Run HTTP suites sequentially on 8443; Phase 4 remains In progress; Phase 5 implementation/candidate checks do not close native/manual gates.

## Update checks (`AUTO_UPDATE_PLAN.md`)

- Phase 1 (in source, not yet in a published release) adds opt-in update checks to the Windows and macOS/Ubuntu companions. Read `AUTO_UPDATE_PLAN.md` before changing them. `UpdateChecker` reads only the fixed GitHub release list and a release's `update.json`/`update.json.sig` over HTTPS on GitHub hosts, follows only allowlisted redirects, enforces size/time limits (including stalled bodies) and sends no version, installation or device identifier. Checks never download or run an installer or archive. A release is offered only when its manifest verifies against a key in `src/PcController.Host/update-signing-keys.pub` and matches its tag, exact release page and asset names.
- Phase 2 (in source, unreleased) adds **Download update** and **Restart to update** to the Windows installer copy only (`WindowsUpdateInstaller.ForInstalledCopy`: the per-user Inno uninstall entry names this folder and an uninstaller inside it); portable ZIP, macOS and Ubuntu copies keep notices. A download happens only on that click, re-reads and re-verifies the release's signed manifest, accepts only the `win-x64`/`installer` asset, checks the exact signed size and SHA-256 while streaming and again through a read-only, read-share handle that stays open until the installer starts. Restart is offered only with no controlling phone, pending power action or open pairing approval; it pauses control and releases input first and stops if that fails. The installer runs `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /relaunch=1 /LOG=…`; `PrepareToInstall` closes the companion with `--exit` and the `UpdateRelaunch` `[Run]` entry in `installer/PCRemote.iss` reopens it. Keep that entry, the AppId in `WindowsUpdateRules` and their portable checks in step. Startup cleans only release files and `.partial` downloads in `%LOCALAPPDATA%\PcController\updates`.
- Automatic checks stay off until the one-time banner question is answered; **Check now** is one explicit check. Preferences live in plain `update-settings.json` (0700/0600, symlinks refused) beside the platform data and never depend on DPAPI/Keychain/keyring storage, so a locked store or failed setup still gets notices. No phone message, field, capability or Host setting is involved. Test shells and automated startup checks pass no update service; tests use in-memory handlers and never contact GitHub.
- The release signing key is offline (`~/.config/pc-remote-release/update-signing-key.pem` by default). Never commit it, put it in CI or GitHub secrets, print it, or sign in CI; `scripts/update-manifest.py` refuses `CI=true` and in-repository key paths. Changing trusted keys is a reviewed edit of `update-signing-keys.pub` and needs a rotation release. From the first release that ships update checks, every release attaches `update.json` and `update.json.sig` created with `scripts/update-manifest.py create`/`sign` after asset verification, and the public copies are re-checked with `verify`. `python3 scripts/update-manifest.py selftest` uses a throwaway key and is safe in CI.
- Phases 3–4 (macOS/Ubuntu replacement, distribution signing) are not implemented; do not start them automatically. The Phase 2 installer path has not run on Windows: its Pascal code is compiled only by the Windows CI job. Never describe an installed update check, tray balloon, menu-bar item or Windows update as verified until a real installed N → N+1 run is recorded in the plan's execution log.

## Required for every new version

- Update the shared `Directory.Build.props` version, Windows app/packaging/installer versions together; Desktop inherits the shared declaration.
- Update `README.md`, **both `AGENTS.md` and `CLAUDE.md`**, `docs/releases.md`, and dated `docs/release-evidence.md` results in the same release work. Refresh behavior, screenshots, setup, and limitations where affected.
- Review `.github/` workflows and templates; update affected files and complete the pull request release checklist.
- Run `./scripts/check-release-docs.ps1`, `./scripts/test.ps1 -Security`, `./scripts/test-certificate.ps1` (Python 3.13+), `./scripts/audit-dependencies.ps1`, and the other release checks required by `AGENTS.md`. Preserve HTTP budget isolation, reserved safety actions, atomic authorization after async body reads, and strict certificate validation with leaf-only migration. Review `.github/SECURITY.md`, verify bundled runtime advisories, package, verify hashes/licenses, and scan source and packages for secrets before publication.
- After separate publication authorization, commit all source/documentation to main, then run the CI `final` dispatch on that commit (the single release gate: every suite on every OS; the workflow no longer runs on every push) to build final packages (or `--final`) from that exact clean commit so informational revisions match the new annotated tag. Push main and that tag, publish accurate Windows/Mac/Ubuntu preview assets and aggregate checksums (plus the locally signed `update.json`/`update.json.sig` from the first release that ships update checks), then verify every public URL, size and digest and the public manifest signature.
- Never call a version finished while its GitHub files, README, agent instructions, or release assets are stale. Never overwrite a published version's tag or assets with a different build.

For documentation-only work, keep the existing version and release assets. If a release cannot be completed, state exactly what remains; do not claim publication or manual testing that did not happen.
